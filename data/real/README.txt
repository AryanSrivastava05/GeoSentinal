GeoSentinel GIS handover PROTOTYPE (FIXED)

Fix applied 2026-09-16:
Previous predictions_new.csv had one row per historical EVENT rather than
one row per VILLAGE (e.g. a village with 5 past events produced 5 rows with
5 different risk scores). When villages.geojson was generated by joining
that file to itself, villages with N event-rows produced N x N duplicate
map points instead of 1 (186 features for 102 real villages; population and
CRITICAL-village counts were inflated ~1.8x as a result).

What changed:
- predictions_fixed.csv: deduplicated to one row per village_id, keeping the
  MOST RECENT event (by event_date in modelling_table.csv) as that village's
  current risk_score.
- villages.geojson: rebuilt to exactly one Feature per village_id (102 total,
  was 186). Villages that only ever had one event keep their original
  coordinate. Villages that were duplicated got ONE new coordinate,
  deterministically generated from their village_id (same script always
  regenerates the same point -> reproducible), inside the same demo bounding
  box as before.

Unchanged (already correct, no action needed):
- candidate_sites.geojson, roads.geojson, study_area.geojson

All geometry in villages/candidate_sites/roads remains explicitly marked
prototype/synthetic because the supplied ML table has no real coordinates.
study_area uses a public Meghalaya state boundary. Replace prototype layers
with authoritative/OSM GIS data before production use.
